# 버스는 많은데, 운행시간도 안정적인가?

서울 행정동의 버스 서비스량과 구간 운행시간 불안정성의 월별 반복성 분석

AI와 함께하는 교통문제 해결을 위한 데이터 분석 공모전 제출용 코드다. 실제 Gate에서 사용한 코드를 보존하고 입출력 경로와 실행 안내를 분리했다. 코드 정리를 위해 계산공식, 표본, 결측처리 또는 결과를 다시 설계하지 않았다.

## 연구목적과 범위

버스 서비스량이 비슷한 지역에서도 날짜별 구간 평균 운행시간 불안정성이 다르게 나타나는 현상이 여러 달에 걸쳐 반복되는지 확인한다. 이후 반복지역 내부의 노선-구간과 시간조건을 진단하고 일 단위 외부조건의 동반관계를 기술한다. 인과효과나 정책 우선순위를 추정하지 않는다.

| 구분 | 고정 범위 |
| --- | --- |
| 공간 | 기존 검증된 2026년 현행 서울 427개 행정동 |
| 원자료 구조감사 | 2025-09~2026-08, 12개월 |
| 기준 평가월 | 2025-09, 2025-10, 2026-01, 2026-02, 2026-03, 2026-04, 2026-05, 2026-06 |
| 탐색 및 설계 월 | 2026-08, 달력월 재계산 결과를 보조로 보존 |
| held_date | 2025-11, 2025-12, 2026-07, 후보 0이 아닌 NA |
| 반복지역 | 소공동, 필동, 신림동, 신사동(강남구), 대치2동, 개포1동, 잠실본동, 잠실6동, 잠실7동 |
| 미시 진단집단 | 지역별 K 최댓값 동률 집단 43개 노선-구간, 비교배경 758개 |
| 대표 사례 | 잠실6동, 소공동 504번(을지로입구.시청입구 → 삼성본관앞), 개포1동 3414번(구룡초교사거리 → 현대아파트경남아파트) |

12개월 연속 결과분석이 아니다. 8개 기준 평가월과 8월 보조 결과를 구분한다. 9개 지역과 43개 구간은 정책 우선지역 또는 새로운 Top 목록이 아니다.

## 핵심 지표

- 운행시간 불안정성 U: 동일 월, 노선, 출발/도착 NODE와 순서, 시간대의 평상 평일 양수 평균운행시간에서 P90−P50. 단위 초. 개별 버스 지연이나 정시성 지표가 아니다.
- 서비스량 C2: 기존 Core 연결 정류장 모집단에서 노선-정류장-시간별 날짜 대표 운행횟수를 구하고, 관측 가능한 시간을 합산한 후 노선을 합산하며 동 안 정류장 중앙값으로 집계한 관측 서비스량이다. 빈칸을 0회로 바꾸지 않고 새로운 반복관측 필터를 추가하지 않는다. 완전한 24시간 총운행량을 뜻하지 않는다.
- 월별 탐색후보: C2와 U 각각의 평균동률 백분위가 75 이상인 교집합. 순위용 사본의 소수점 8자리 처리는 기존 코드 그대로다.
- 반복정보: 유효 평가월 수 V, 후보 월 수 K, R=K/V. V=0이면 R=NA다. 새로운 지속후보 cutoff는 없다.
- 일별 사례: M2 저장 E(동일 세부키 P50 대비 편차, 초)와 I(저장 P90 도달 표시)를 시간과 구간 두 수준에서 동일가중 집계한다.

세부 산식과 제한은 [방법론](docs/methodology.md), [변수 사전](docs/variable_dictionary.md)에 있다.

## 환경

기존 환경은 Python 3.12.14, pandas 2.2.3, numpy 2.3.5다. 나머지 실제 사용 패키지와 버전은 `requirements.txt`에 고정했다. 공간처리에는 기존 matplotlib Path와 VTK 기반 투영을 유지했다. 새 GeoPandas/Shapely 구현으로 교체하지 않았다. Excel은 openpyxl로 읽는다.

```bash
python -m venv .venv
python -m pip install -r requirements.txt
```

가상환경 활성화는 운영체제의 Python 안내에 따른다. 설정이 필요하면 `config.example.json`을 `config.local.json`으로 복사하고 원자료 또는 개인보관 중간자료의 상대경로를 지정한다. `config.local.json`은 업로드하지 않는다.

## 데이터 확보

원자료는 대용량이며 역사 스냅샷, 출처별 이용조건과 원본 무결성을 따로 관리하므로 GitHub에 재배포하지 않는다. 개인정보가 없는 공개 원자료라도 이번 저장소에는 넣지 않았다.

[데이터 안내](data/README.md)에 실제 사용 자료명, 제공기관, 공식 URL, 기간, 파일명을 기록했다. 최신 마스터로 과거를 대체하지 않는다. 공식 사이트에서 현재 내려받는 파일이 기존 파일과 동일하다는 보장은 없으므로 원본 해시와 과거 보관본을 확인해야 한다. 인증키를 코드에 입력하는 절차는 없다.

## 실행순서

각 진입점을 인자 없이 실행하면 기존 Gate 명령 순서만 표시한다. `--check-inputs`는 경로 존재를 확인하고 `--run`은 원본 스크립트를 실행한다. 원자료가 없으면 입력을 요구하며 임의 숫자 또는 0을 생성하지 않는다.

```bash
python src/01_data_audit.py --run
python src/02_build_bus_metrics.py --run
python src/03_multimonth_recurrence.py --run
python src/04_robustness_checks.py --run
python src/05_segment_diagnostics.py --run
python src/06_temporal_patterns.py --run
python src/07_pair_route_diagnostics.py --run
python src/08_daily_case_analysis.py --run
```

7단계 이전에 기존 M3A 감사 중간자료가 필요하다. 재구축은 `python src/run_gate.py environment-audit --run`으로 원래 감사코드를 실행한다. 도로속도, 교차로, 전용차로의 정밀 공간결합은 여전히 held_geometry이며 원인분석으로 승격하지 않는다.

8단계 이전에 C2A의 기존 생활인구 노출 패널과 서울 ASOS 108 공식 일자료가 필요하다. C2A 전체 외부노출 감사 재현은 `python src/run_gate.py exposure-preparation --run`이다. 이 준비단계에는 당시 감사에 사용한 AWS 원자료도 필요하지만 일별 Main에서는 AWS를 사용하지 않는다. 준비된 노출 패널은 `saved_gate_dirs`로 지정할 수도 있다. C2A의 기준 생활인구 계산을 새로 작성하지 않았다.

버스 원자료를 다시 읽는 단계는 오래 걸릴 수 있다. 기존 Gate 중간자료를 개인보관하고 있다면 `config.local.json`의 `saved_gate_dirs`에 지정해 필요한 단계부터 재현할 수 있다. 코드 내부의 원본 해시와 키 검증은 유지한다. 저장한 pickle은 신뢰할 수 있는 본인의 산출물만 사용한다.

## 재현 QA와 주의사항

```bash
python src/verify_submission.py
```

이 명령은 동결 범위, 공개 CSV와 코드 무결성을 확인한다. 전체 원자료 분석을 실행하는 명령이 아니다. 제출 정리 과정에서 실제 실행한 재현 QA의 범위는 [QA 기록](qa/reproduction_QA.md)에 구분했다. 전체 원자료 재실행을 완료했다고 주장하지 않는다.

- held 월은 NA다. 1월은 Main에 포함하고 월 전체 제외 QA를 유지한다.
- 2→3 제외, 운행시간 0 비유효, 운행횟수 빈칸 보존, 충돌 키 보류를 바꾸지 않는다.
- 생활인구 Main은 C2A-R 승인 6개 동과 세 성분을 각각 사용한다. 강남구 3개를 인접동으로 대체하거나 성분을 합산하지 않는다.
- 강수는 160개 계획 평일 중 공식 일별 표에 양수 45일, 명시적 0 15일, 비수치 100일이다. 비수치는 NA이며 일반적인 모든 건조일 비교로 해석하지 않는다.
- E/I의 일 단위 결합은 버스 시간코드 시작/종료를 추정하지 않는다. 효과, 원인, 정책 우선순위의 근거로 확대하지 않는다.
- `outputs/legacy/`는 기존 8월 설계와 달력월 전환 QA에만 쓰는 과거 집계결과다. 8개월 Main이나 새 달력월 8월 값을 대체하지 않는다.

AI는 코드 작성과 감사 보조에 사용했다. 제출 분석은 기존 동결 규칙을 구현한 기술통계와 반복성 및 사례분석이며 머신러닝 예측모형을 추가하지 않았다.
