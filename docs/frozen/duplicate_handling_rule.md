# Gate 2-F0D 중복, 충돌, 0 및 특수 ID 처리

설계 버전 F0D-1.0. 원본 불변, 제외 및 보류 사유 보존을 원칙으로 한다.

## 중복 판정 키

| 자료 | 일별 행 키 | 값 필드 |
| --- | --- | --- |
| 운행시간 | 날짜 + 노선 ID + 출발 ID + 도착 ID + 출발 순서 + 도착 순서 | 전체 운행시간과 00~23시의 원문 값 모두 |
| 운행횟수 | 날짜 + 노선 ID + 정류장 ID + 정류장 순서 | 전체 운행횟수와 00~23시의 원문 값 모두 |

시간대를 긴 형태로 바꾸기 전에 모든 ZIP과 CSV를 합친 연구기간 범위에서 중복을 검사한다. 한 파일 안과 여러 파일 사이를 함께 확인한다. 파일명이나 입력순서에 따라 중복 여부를 달리하지 않는다. 동일 ZIP의 재업로드는 바이트 해시와 내부 CSV 해시로 계보를 연결하고, 이름의 `(1)`만으로 신버전 또는 중복이라고 판정하지 않는다. 신규 첨부의 이러한 검사는 다음 Gate에서 수행하며 이 Gate에서는 읽지 않았다.

## 완전 동일 중복

같은 키에서 원자료 전 컬럼의 셀 문자열이 모두 같으면 하나의 관측으로 유지한다. 최초 보존행의 출처는 파일 해시, CSV 이름, 원본 행번호의 사전 고정 정렬로 정하되, 모든 중복 출처를 별도 목록에 보존한다. 유지할 관측 값이 같기 때문에 이 출처 정렬은 값 선택이 아니다. n개이면 추가행 n-1개를 제거 건수로 기록한다. 행 지문은 후보 탐색용으로만 쓰고 모든 필드를 정확 비교한다.

## 값충돌과 표기 불일치

완전 중복을 먼저 접은 뒤 같은 키에 서로 다른 원문 행이 둘 이상 남으면 `conflict_pending`으로 분리한다. 총괄 컬럼만 다르거나 24개 중 한 시간대만 달라도 해당 날짜와 키의 **24시간 행 전체**를 분석에서 보류한다. 안전한 셀만 임의로 골라 합성하지 않는다. 자동 평균, 최소, 최대, 최신 업로드, 첫 행, 마지막 행 선택을 금지한다.

`1`과 `1.00`처럼 숫자로 같고 원문 표기만 다른 경우도 `format_only_conflict`로 기록하고 동일 보류 원칙을 적용한다. 사전에 검증된 공급자 표준변환이나 공식 정정 근거 없이 표기를 같게 만들어 해소하지 않는다. 빈칸과 0은 어떠한 경우에도 동등값으로 취급하지 않는다.

공급자가 정정본과 적용 날짜 및 키를 명시하여 정답이 확인된 경우에만 그 근거에 따라 해제한다. 정정 전후 값을 보존하고 원본 해시, 정정 근거, 해제 날짜, 영향 범위를 기록한다. 답변을 확보하지 못해도 충돌 키를 보류한 상태로 나머지 관측의 실행 적격을 평가할 수 있다. 한 키의 충돌 때문에 그 날짜 전체를 삭제하지 않는다. 충돌은 해당 키의 관측일 및 셀 커버리지를 낮추며 월 분모 N_m을 낮추지 않는다.

F0S에서 확인한 2026-06-30의 51개 충돌 키는 이 규칙의 기존 사례다. 102개 서로 다른 행 중 어떤 행도 이번 Gate에서 정답으로 채택하지 않았다.

## 0, 빈칸 및 예외 숫자

- 운행시간 0: 원문과 플래그를 보존하고 P90-P50 등의 유효값에서는 제외한다. 시간0을 미운행으로 단정하지 않는다.
- 운행횟수 빈칸: 결측으로 유지한다. 행부재와도 구분한다. 0회로 대입하지 않는다.
- 명시적 운행횟수 0: 빈칸과 다른 기록된 숫자0으로 보존한다. 자료 정의가 허용하는 정상 횟수 필드이면 관측값에 포함한다. 실제 미운행의 확정 의미는 공급자 근거 없이 주장하지 않는다. F0S 검사자료에는 명시적 0이 없었으므로 새 기간에서 나타나면 값 구조감사에서 정의 호환성을 먼저 확인한다.
- 음수, 비숫자, 유한하지 않은 값: 별도 오류 보류. 횟수의 새로운 소수 값이나 음수 출현은 반올림하지 않고 스키마 의미를 확인한다. 단위 변화 의심이 해결되지 않으면 해당 자료기간을 `held_structure`로 보류한다.
- 시간 총괄 컬럼: 보존 및 중복감사에만 쓰고 24시간 평균으로 간주하거나 Main 계산에 쓰지 않는다. 횟수 총괄 컬럼도 시간대 관측 부분합을 채우는 용도로 쓰지 않는다.

## ID와 순서

ID는 문자열로 읽고 원문을 보존한다. 정수형 엑셀 셀을 정확한 정수 문자열로 변환하는 검증된 무손실 변환만 허용한다. 접두부 추측, 선행0 추가, ARS와 NODE_ID 변환 추정, 이름 유사도 매칭은 금지한다. 순서는 정수 및 양수 여부를 검증한다. 운행시간은 도착 순서-출발 순서=1인 인접 구간을 사용하며 그 외는 구조보류한다. 키가 같은 물리적 도로의 장기 동일성까지 보증하지 않음을 명시한다.

운행횟수의 노선ID `0`, 4자리 정류장 ID, 순서 `999` 조합은 `special_id_record`로 원형 보존하고 정책 Core와 C2에서 제외한다. 이를 일반 9자리 NODE_ID로 바꾸지 않는다. 아직 의미가 불명확한 다른 형식도 `unknown_id_format`으로 별도 보류한다. 일반 9자리라는 사실만으로 서울 정책대상이라고 판단하지 않고 공식 유형과 키 및 좌표 근거를 요구한다.

## 2→3 및 기타 양수 큰 값

출발순서=2이고 도착순서=3인 시간 구간은 **모든 월의 Main과 지정 강건성에서 동일하게 제외**한다. Gate 1C에서 확인된 반복적 극단값 위험에 대한 기존 설계를 승계하며, 각 월 값을 확인한 뒤 제외 여부를 바꾸지 않는다. 첫 구간 1→2, 종점, 양수 큰 값 일반을 일괄 추가 제외하지 않는다. 물리적 오류임을 전부 확정했다고 설명하지 않는다.

2→3 시간 구간 제외를 해당 노선 전체 또는 그 정류장의 모든 횟수 삭제로 확대하지 않는다. C2의 정류장 모집단은 살아남은 정책 시간 Core의 양끝에서 정의하며, 다른 유효 구간이 같은 정류장을 포함하면 그 관측 서비스량은 기존 산식대로 사용한다.

## 필수 기록

source_id, zip_sha256, csv_sha256, source_row, data_kind, raw_key, canonical_key, duplicate_group, duplicate_extra_rows, conflict_type, retained_or_held, reason_code, correction_evidence, version을 보존한다. 날짜별 및 월별 완전 중복 추가행, 충돌 키 수, 보류행 수를 구분한다. 중복 관련 행 수와 추가행 수를 혼동하지 않는다.
